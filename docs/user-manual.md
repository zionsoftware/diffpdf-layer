# ユーザーマニュアル

対象: diffpdf-layer 0.2.0。更新日: 2026-10-26。

## 1 このツールで確認すること

担当・確認・審査・承認のPDFを比較し、レイヤーごとの内容の一致状況と業務上のPASS・FAIL・UNVERIFIABLEを確認します。担当・確認は必須で、審査・承認はそれぞれ省略できます。基準PDFは、指定された最後の工程から自動選択されます。

比較は構造・内容を対象とします。原本PDFは変更しません。見た目や記載内容の正しさ、チェックマークの視認性は目視で確認してください。

## 2 起動と準備

通常インストール済みのPython 3.14と、vendorへ配置したpypdf 6.20.1を使用します。start.batを起動すると画面が開きます。初期準備は[インストール手順書](installation-guide.md)を参照してください。実行時のダウンロード・pip・仮想環境作成はありません。

PDF保存にはReportLab・Pillow・charset-normalizerと日本語TrueTypeフォントも必要です。通常のWindowsではMSゴシックを使用します。依存の配置方法と任意フォントの指定は、インストール手順書のPDF出力の章を参照してください。

## 3 PDFを役割別に指定する

各欄の「選択」でPDFを指定します。「解除」でその役割の指定を外せます。フルパスを直接入力することもできます。

| 役割 | 指定条件 |
|---|---|
| 担当 | 必須 |
| 確認 | 必須 |
| 審査 | 任意 |
| 承認 | 任意 |

すべて指定すると承認が基準です。承認を省略すると審査、審査と承認の両方を省略すると確認が基準です。審査を省略し、承認を指定することもできます。画面の基準PDF表示で確認してください。

業務レイヤー名は「担当」「確認」「審査」「承認」に完全一致させます。「担当者」等の別名や余分な空白を、自動的に同じ名前とは扱いません。同じPDFを複数の役割に指定することはできます。

## 4 比較を実行して表を読む

「比較開始」を押します。2ファイルなら1組、3ファイルなら3組、4ファイルなら6組を比較します。処理中は入力を変更できません。「中止」で処理を止めると判定結果は残りません。GUIの比較待機上限は180秒です。

「基準PDFとの比較」タブは、基準PDFのレイヤーを縦軸、各役割のPDFを横軸にした表です。各セルはそのPDFと基準との比較です。基準欄の「基準」は、自己一致を検証した意味ではありません。

| 比較項目 | 読み方 |
|---|---|
| PDF全体 | PDF本体・レイヤーなし・全レイヤーを集約した一致状況 |
| PDF本体 | ページ数・用紙領域・回転・対応文書属性など |
| レイヤーなし | どのレイヤーにも属さない本文描画・注釈など |
| 各レイヤー名 | 同一名のレイヤー内容と関連設定の比較 |
| 業務判定 | 工程ごとの一致必須項目から判定した結果 |
| 基準PDF外 | 入力のいずれかにあり、基準PDFにない追加レイヤー |

内容の判定は一致・不一致・検証不能です。レイヤーの追加・削除やフォントのみの変更も、不一致として理由を表示します。PDF全体は不一致を優先し、不一致がなく検証不能を含めば検証不能、すべて一致なら一致となります。

「全組合せの結果」タブには、前工程同士を含むすべての組のPDF全体・業務判定を表示します。各タブの結果行を選ぶと、差異や検証不能の理由、注釈の作成者記録を詳細欄で確認できます。

## 5 業務判定を読む

| 比較する工程 | 一致必須の業務レイヤー | 差異を許容する業務レイヤー |
|---|---|---|
| 承認と審査 | 担当・確認・審査 | 承認 |
| 承認と確認 | 担当・確認 | 審査・承認 |
| 承認と担当 | 担当 | 確認・審査・承認 |
| 審査と確認 | 担当・確認 | 審査・承認 |
| 審査と担当 | 担当 | 確認・審査・承認 |
| 確認と担当 | 担当 | 確認・審査・承認 |

PDF本体・レイヤーなし・上記4名称以外のレイヤーは、すべての比較で一致必須です。

一致必須の項目に不一致があればFAILです。不一致がなく、必要な項目を比較できなければUNVERIFIABLEです。必要な項目をすべて比較して一致していればPASSです。不一致と検証不能が混在する場合はFAILを優先し、検証不能の理由も残します。

たとえば承認レイヤーだけが審査PDFと異なる場合、PDF全体は不一致でも、承認と審査の業務判定はPASSです。必須の担当レイヤーが両PDFにない場合は、一致確認ができないためUNVERIFIABLEとなります。

## 6 結果を保存する

画面右側の保存形式でTXTまたはPDFを選び、「結果を保存」を押します。保存先を選んで確定してください。既定名はcmp.txt、cmp.pdfです。既存の入力以外の出力を指定すると置き換えるため、過去の結果を残す場合は保存先を変更してください。

| 形式 | 内容 |
|---|---|
| TXT | UTF-8の比較表、全組合せ、理由、作成者参考情報 |
| PDF | 日本語フォントを埋め込んだ表形式。改ページ時は表見出しを繰り返す |
| CSV | ファイル情報・主表・全組合せ・明細の複数セクション。UTF-8 BOM付き |
| JSON | schema_version 4。役割、ファイル情報、組合せ、比較明細を構造化 |

各入力のフルパス、最終更新日時（UTC、タイムゾーン付き）、容量のバイト数、SHA-256の先頭12桁を保存します。ハッシュの表示例はabcdef-123456です。ハッシュは実際に解析したバイト列から計算し、内容の一致状況とは別に記録します。

入力PDFへの保存は拒否します。PDF生成に失敗した場合は既存出力を保持します。PDF出力の依存やフォントが不足している場合も、比較結果からTXTを保存できます。

## 7 コマンドラインを使う

担当と確認だけを比較する例です。出力先フォルダーは先に作成してください。

```bat
start.bat --cli "C:\PDF\担当.pdf" "C:\PDF\確認.pdf" --output "C:\結果\cmp.txt"
```

審査を省略して承認を指定する場合は、役割別オプションを使います。

```bat
start.bat --cli --responsible "C:\PDF\担当.pdf" --confirmation "C:\PDF\確認.pdf" --approval "C:\PDF\承認.pdf" --output "C:\結果\cmp.pdf"
```

審査は--reviewで指定できます。位置引数は担当・確認・審査・承認の順です。3番目の位置引数は審査であり、承認ではありません。位置引数と役割別オプションは併用できません。

--jsonではJSONを標準出力へ表示します。終了コード0はコマンド処理の完了を意味し、PASSや全体一致を意味しません。自動処理ではerrorsとpairsのoverall・businessを確認してください。通常の環境・入力・ファイル解析・保存エラーは終了コード2です。

## 8 エラーや判定不能への対処

担当・確認が未指定なら指定してください。暗号化PDF、壊れたPDF、未対応構造は検証不能となります。同名レイヤーが重複する場合も、その名前を安全に対応付けできません。詳細に表示された理由を確認してください。

読み込み中のファイル変更を検出した場合は、PDFを保存し終えてから再比較してください。読めなかったファイルやサイズ上限超過の場合はハッシュを取得不能と表示します。壊れたPDFでも全バイトを読めた場合は、そのハッシュを記録します。

旧schema_version 2・3の保存結果は、新しい業務判定を証明するものではありません。元PDFを指定して再比較してください。現在のGUIに保存JSONを開く操作はありません。

## 9 比較の範囲と参考情報

1ファイル128 MiB以下、1～2000ページを対象とし、未対応のPDF構造は検証不能とします。対応範囲の詳細は[対応構造一覧](supported-structures.md)を参照してください。

注釈の作成者名はPDFに記録された値を集計した参考情報です。実際の操作者・最終編集者を証明しません。作成者名だけの変更は内容不一致にせず、名前別件数・未設定件数・構成変更として表示します。集計未完了と注釈なしは区別します。

比較結果は、文字の遮蔽や重なり、見た目の完全一致、記載内容の妥当性を保証するものではありません。業務判定に加え、必要な目視確認を行ってください。
