# 技術調査と設計判断

更新日: 2026-10-16。対象: Python 3.14.8 / pypdf 6.20.1。順序非依存の内容比較と注釈作成者名の分離を正式な仕様とする。

## 根拠と依存

前回の調査では [PDF 32000-1:2008](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf) のoptional content・XObject・注釈を参照した。今回の実装では、インストール済みpypdf 6.20.1の `generic.ContentStream`、間接参照、`_cmap.py`、`_codecs` の実装と、保存済みPDF-XChange Editor 11.1出力を確認した。

pypdfの文字抽出には、未知のEncodingを代替値へフォールバックする経路がある。今回の二次比較ではその推測を利用せず、限定したCMapを厳密に検査する専用処理を実装した。標準EncodingとAdobe glyph名の表は、バージョンを固定したpypdfのデータを使用する。追加ライブラリ・外部フォント・バイナリ・通信は不要。

## グループと影響範囲

- `Snapshot.groups` にPDF本体、レイヤーなし、各OCGを保持し、エラーを各グループへ格納する。重なり順の補助判定は持たない。
- 1番目を基準に各比較対象を比較する。レイヤー名の和集合を使い、追加・削除を扱う。重複名は当該名を検証不能とする。
- ページツリーとページ属性をPDF本体へ、描画・注釈を所属グループへ分離する。未所属は通常のレイヤーなしである。
- OCGの登録一覧が壊れた場合は空の一覧とみなさない。OCMD・未登録参照を未所属へ振り替えない。
- 独立したq/Q区間で問題があれば所属グループへ限定する。未閉鎖状態・未知の所属・共有状態の影響が不明な場合は範囲を広げる。
- URI LinkはActionの辞書・URI・属性を比較するだけで実行しない。動的Actionや関連注釈は所属先を検証不能とする。

## 描画・リソースの依存

命令と実際に参照するフォント・XObject・ExtGState等を一緒に正規化する。未使用のページフォント、APリソース、AcroForm DRを注釈へ丸ごと取り込む方式は廃止した。DAの名前はAcroForm DRを優先して解決し、そこにない名前だけページリソースへフォールバックする。

q/Q内の独立した描画は後続へ状態を漏らさないため、先行するDEMOの全描画をレイヤーの比較へ付け加えない。q/Q外に残る行列・色・線・透明度・文字状態は追跡して、使用する描画へ取り込む。ExtGStateの部分更新は属性ごとに保持し、後の部分更新で以前の透明度が消えないようにする。上書き済みの状態や、塗りにしか関係しない透明度を使わない線描画などは、その依存から外す。

完全な描画状態インタープリターではない。ページ本文のq/Q外でクリップを設定する構造や、色空間・Fontを持つExtGState等で依存を確定できない場合は検証不能とする。Form・APは暗黙に描画状態を保存・復元するので、全ストリームを一つの保存区間として検査し、最初のクリップも比較から落とさない。Form内部のOCG分離は未対応。

## 通常比較とフォントの二次比較

各値は通常の完全な正規化値と、フォントに限る二次比較値を保持する。フォント辞書や埋め込みプログラムは通常比較に必ず残す。

1. 通常値が一致すれば「一致」。文字復元を推測する必要はない。
2. 差がある場合だけ、使用フォントの宣言から文字コードをUnicodeクラスターへ復元する。未定義・重複・曖昧な対応や未知のEncodingがあれば、そのグループを検証不能とする。
3. サイズ、Tm / Td等の配置、TJ調整、色、透明度、図形、画像、注釈属性等を保持した二次値を比較する。ToUnicodeが複数文字を返す1コードを、2つの別コードと同一視しない。Twが単一バイト0x20だけに作用する点も保持する。
4. 二次値が一致し、フォントの通常値に差がある場合だけ「一致（フォントのみ変更）」とする。変更名・フィンガープリントを機械可読な `font_changes` に格納する。

6文字のサブセット接頭辞やTfのリソース名だけの差は保存識別子として正規化する。埋め込みプログラムそのものの書き換えは通常値に残るため、文字を復元できる場合にだけフォント変更付き一致となる。

この判定は明示した配置命令と宣言された文字内容等の構造的一致である。字形・字幅・暗黙の字送り・画素位置をレンダリングして証明するものではない。CMapの意味を超える推測やフォントプログラムの正当性の検証は行わない。対応Encoding/CMapの詳細は [対応一覧](supported-structures.md) を参照。

## 独立した描画単位の順序非依存比較

間接参照は実オブジェクトへ解決し、番号・Generation・格納順・辞書キー順を比較しない。ロスレスストリームは展開して比較する。注釈は同一内容の重複数を保持するマルチセットとして比較する。

本文は、q/Q・marked content・BT/ET・パスの完結したトップレベル単位へ分割する。OCGには独立した状態保存と単一所属を要求する。使用リソースを解決し、継承した行列・色・線幅・透明度・文字状態を使用箇所へ結び付けた完全な `Content` を作る。ページ番号・グループを保持したまま、その単位全体だけを `combine(..., unordered=True)` でマルチセット化する。重複数を消すset比較や生の命令列のソートは行わない。

ページの単純なq/Q・単一OCG囲みに複数のパス・BT/ET・Doが入る場合、クリッピングや追加の入れ子、呼び出し先OC等がないことを検査し、その時点の継承状態を再走査で付与して個別の完結した描画へ分離する。BT/ET内の複数Tjや、一つのパス内のサブパスは分割しない。Form / APではこのページ用の分割を適用しない。

内部の文字順・パス構造・行列適用順は保持する。Form / APは暗黙のq/Qで全体を包む一単位として扱い、内部命令を並べ替えない。q/Q外のクリップ、複数所属、未完了のパス、未知命令等で独立性や状態を確定できない場合は検証不能にする。TDが暗黙に更新するleading、T*で使用後にTLで上書きするleadingも追跡し、テキスト位置の変化を落とさない。

本プログラムは、PDF本体・レイヤーなし・各OCGレイヤーの内容を比較する。オブジェクトの重なり順や視認性は判定しない。チェックマーク・注記の視認性や妥当性は、担当者・確認者・審査者が目視で確認する。注釈矩形の交差検査、遮蔽警告、画素比較は行わない。

## 注釈の作成者情報

注釈辞書を内容へ正規化する際に `/T` を除き、その他の文字列や独自属性は残す。`/Contents` / `/Subj` は内容、`/M` / `/CreationDate` / `/NM` は従来どおり保存由来の除外属性とする。作成者名を読めない間接参照のpypdf警告を内容へ波及させないため、内容解析を終えた後に独立した走査で `/T` を取得する。

`Snapshot.authors` はレイヤーなしと各OCGの `AuthorInfo` を保持する。名前別 `counts`、未設定 `unset_count`、所属が既知の取得不能件数 `unreadable_count`、完全性 `complete`、グループ存在 `group_present`、理由 `errors` を持つ。存在不明はnull、存在しないレイヤーはfalse。所属が不明な注釈の数を特定グループに割り振らない。取得不能なら部分集計を明示し、変更有無をnullにする。

比較行の `reference_authors` / `target_authors` は内容ステータスとは独立する。両方の集計が完全な場合のみ `(counts, unset_count)` の差を `authors_changed` に記録する。同じ内容が重複する注釈の個別対応は推測しない。このため、構成が同じでも個々の作成者名の付け替えを検出するとは限らない。

注釈に記録された作成者名は、内容の同一性判定から除外し、参考情報としてグループごとに表示する。作成者名の変更だけでは不一致としない。作成者名は実際の操作ユーザーや最終編集者を証明する情報ではない。WindowsユーザーやADアカウントの取得・認証は行わない。

## 出力と制限

Reportに総合ステータスは持たせない。JSON schema_version 3は基準・比較対象・各行のステータス・既存の `font_changes` に加え、双方の `AuthorInfo` と `authors_changed` を構造化して保持する。GUI詳細とTXTは共通の `row_details` を使用する。CSVは従来の5列に双方の作成者集計と構成変更の3列を追加する。CLIの終了コードはレポート生成処理の成功・エラーだけを表す。

schema_version 2の読み込みは旧補助行を除去し、保持する各行を検証不能へ変換する。旧判定を詳細に残し、元PDFでの再比較を案内する。作成者集計は未取得として保持し、旧仕様の判定を現仕様の一致とみなさない。version 3の読み込みは集計の必須フィールド・件数・完全性・構成変更フラグの整合を検査する。

数値はpypdfの出力用丸めを使わず、元の浮動小数値から正規化する。生PDF・展開データに有効数字15桁等の字句上限を設ける。フォントやバイナリ中の数字にも反応する保守的な制限である。ファイル、ストリーム、命令数、再帰、CMapにも上限を設ける。

追加検証が必要なのは、複雑なCMap、縦書き、Popup / IRT、条件付きOCG、標準設定以外の最適化・増分保存、大規模データ、Windows各版・DPI・オフライン実機環境である。標準設定の最適化保存1例は、その後の[実機検証](xchange-validation.md)で確認した。実出力と生成データを超えた互換性は主張しない。現行仕様・制限の体系的な説明は[正式文書一覧](README.md)を参照する。
