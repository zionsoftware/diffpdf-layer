# 要求定義書

対象: diffpdf-layer 0.2.0。文書整備基準日: 2026-10-26。

## 1. 位置付けと根拠

本書は、PDFの内容同一性検証に必要な目的・利用者の要求を定義する。[要件定義書](software-requirements.md)が検証可能な条件へ展開する。実現方法は[基本設計書](basic-design.md)、実際の確認範囲は[テスト仕様書・検証結果](test-specification.md)を参照する。

要求の根拠は、文書整備前のREADME、[技術調査](technical-investigation.md)、[対応構造一覧](supported-structures.md)、[開発報告](development-report.md)に記録された現行製品仕様である。**本書の要求IDと要求の分類は、これらの資料から今回再構成したものであり、過去に同じID・文章で明示的に合意されたことを示さない。** コードから確認した上限値・起動条件は、利用目的から導いた過去の要求とせず、要件定義書で現行実装上の条件として区別する。

## 2. 背景・課題

PDFの本文・図形・注釈が変更されたとき、どの内容グループに変更が含まれるかを確認したい場合がある。ファイル全体のバイト比較だけでは、保存日時、内部参照番号、圧縮方式などの保存差と、文字・位置・図形などの実質的な差を区別しにくい。また、あるレイヤーの変更によって、内容が変わっていない別レイヤーまで不一致になると確認箇所を絞りにくい。

本ソフトウェアの目的は、複数のPDFを比較し、PDF本体・レイヤーなし・各OCGレイヤーの内容が基準PDFから変更されていないかを、対応範囲と検証できない理由を伴って確認できるようにすることである。

## 3. 想定利用者

| 役割 | 利用目的 |
|---|---|
| PDFを作成・編集する利用者 | 保存後の変更範囲や、維持した内容を確認する |
| PDFの内容を確認する利用者 | 基準との内容差をグループごとに確認する |
| 比較結果を参照する利用者 | 保存された判定・理由・参考情報を参照する |

担当・確認・審査・承認の工程を扱う。担当・確認は必須、審査・承認は任意とし、指定された最後の工程を基準にする。記載内容の正しさと視認性の確認は利用者が行う。

## 4. 要求と成功条件

以下の成功条件は対応範囲内での達成を意味する。全PDF仕様や見た目の完全一致を保証する条件ではない。

| 要求ID | 要求・必要な理由 | 成功条件 | 展開先 |
|---|---|---|---|
| UR-001 | 基準PDFから内容が変わっていないかをグループ別に確認したい | 基準と各比較対象について、PDF本体・レイヤーなし・各OCGの判定が得られる | FR-001～FR-006 |
| UR-002 | 無関係なレイヤーの変更に影響されずに確認したい | 所属と影響範囲が分かる変更・解析失敗は、そのグループへ限定される | FR-004、FR-005、FR-015 |
| UR-003 | 文字・図形・注釈等の実質的な変更を検出したい | 文字、配置、形状、色、線幅、透明度、資源、個数等の差が検出される | FR-008、FR-009 |
| UR-004 | 保存方式や独立オブジェクトの並びの差で誤判定したくない | 対応する保存差と安全に分離した単位の順序だけの差は一致となり、単位内部の意味を失わない | FR-007、FR-010 |
| UR-005 | 安全に同一性を確認できない場合は明確に知りたい | 未対応・破損・所属不明等を一致にせず、検証不能と理由が得られる | FR-015、FR-023、NFR-004、NFR-005 |
| UR-006 | フォントだけの変更と内容変更を区別したい | 文字と非フォント属性の一致を安全に確認できる場合に限り、専用判定と差が得られる | FR-011 |
| UR-007 | 注釈の作成者記録を内容と切り離して参照したい | 作成者名だけでは不一致とせず、名前別件数・未設定・集計の完全性・構成変更が参照できる | FR-012～FR-014 |
| UR-008 | 入力順を確認し、操作中の処理を制御したい | GUIで基準を指定・変更し、比較・詳細確認・中止ができる | FR-016～FR-018、NFR-006 |
| UR-009 | 比較結果を保存・再利用したい | 読みやすい記録と機械処理用データを、内容判定・補足情報を保って保存できる | FR-019～FR-021、FR-024 |
| UR-010 | 入力PDFを改変せずに検証したい | 比較による原本変更がなく、結果保存で入力PDFを上書きしない | FR-022、NFR-003、NFR-007 |
| UR-011 | 外部通信に依存せず、準備したソースで利用したい | Windowsの通常Pythonと手動配置の依存ソースで、実行時のインストール・通信なしに起動できる | NFR-001、NFR-002、NFR-008 |
| UR-012 | 仕様と確認範囲を追跡し、継続保守したい | モジュール、要件、再実行可能なテスト、実機記録の対応と未確認範囲が分かる | NFR-008、NFR-009 |

## 5. 工程別比較の追加要求

2026-10-26に承認された変更計画に基づき、入力の役割指定、最後の工程の基準化、全組合せの比較、内容の三分類、業務判定、横並び表、ファイル情報・SHA-256記録、TXT・PDF出力を追加する。具体的な業務判定表・例外条件・保存形式は[工程別比較の仕様](workflow-specification.md)を参照する。

## 6. 対象外

以下は本ソフトウェアの目的に含めない。

- PDFの視認性、文字の遮蔽、重なりによる読みやすさの自動判断。
- 描画順序や重なり順それ自体の一致確認。
- 注記・チェックマーク等の記入内容の妥当性判断。
- 注釈の作成者本人の認証、実際の操作者・最終編集者の特定、編集履歴の追跡。
- PDFの編集、修正、注釈や作成者名の変更。
- 全PDF仕様への完全対応、レンダリング結果の画素一致保証。

本プログラムは、PDF本体・レイヤーなし・各OCGレイヤーの内容を比較する。オブジェクトの重なり順や視認性は判定しない。チェックマーク・注記の視認性や妥当性は、担当者・確認者・審査者が目視で確認する。

注釈に記録された作成者名は、内容の同一性判定から除外し、参考情報としてグループごとに表示する。作成者名の変更だけでは不一致としない。作成者名は実際の操作ユーザーや最終編集者を証明する情報ではない。
