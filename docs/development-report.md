# グループ別比較への仕様変更・開発結果

更新日: 2026-10-16。今回の依頼を正式仕様として、従来のベースPDF・全組み合わせ・レイヤー名集合一致の方式を置き換えた。

## 実装した仕様

- 1番目を基準PDFにし、2番目以降の最大3ファイルと比較する。比較対象同士の組は生成しない。
- PDF本体、レイヤーなし、各OCGを独立して解析・比較する。Reportの総合ステータスを廃止した。
- レイヤー名の和集合で新規追加・削除に対応。重複名や局所的な未対応構造は、影響範囲を限定して検証不能にする。
- 未所属の描画・注釈・URI Linkをレイヤーなしへ分類。DEMO描画やリンクを特別扱いして除外しない。URIや動的Actionは実行しない。
- 共有リソースを使用先へ結び付け、ページやAcroFormの未使用フォントを無関係な注釈へ含めない。状態設定もレイヤーごとに射影する。
- 通常比較の後、フォントと文字内容の差を分離した二次比較で「一致（フォントのみ変更）」を扱う。専用ステータスと `font_changes` をJSONへ出力する。
- オブジェクト番号、Generation、格納順、辞書順、対応するロスレス圧縮、注釈の保存日時・識別子を正規化する。
- 注釈は重複数を保持したマルチセットで比較。交差するRectの順序やグループ間描画順は補助項目「合成順序」へ分離する。
- GUIの基準表示・並べ替え・各判定・詳細表示を更新。TXT / CSV / JSONも同じグループ結果を保存する。
- GUIの待機スレッドがTkオブジェクトを保持しないようにした。通常Pythonを使うstart.bat、手動vendor配置、原本保護を維持した。

## 判定方法と制約

フォント辞書を丸ごと捨てて一致にする方式は採用していない。通常値に辞書、Descriptor、埋め込みデータ、Encoding、ToUnicodeを保持する。通常値に差があるときだけ、対応したEncoding/CMapから実際に使用したコードをUnicodeクラスターへ復元して二次比較する。

明示した配置・サイズ・色・透明度、TJ調整、Twの0x20規則、図形・画像・その他の注釈属性を残す。文字が不明、対応が重複・曖昧、DAが自動サイズ等なら無理にフォント変更付き一致としない。Base14と同じ名前を申告する埋め込みフォントであっても、暗黙Encodingを推測しない。

内部名・CSSの申告名を表示するが、正式なフォント名とは断定しない。同じプログラム・実質属性でサブセット接頭辞やリソース識別子だけが異なる場合は通常一致になる。字形・字幅・暗黙の字送り・画素位置を同一と保証する判定ではない。

## 自己レビューで修正した問題

- Form / APの暗黙の状態保存を考慮し、ストリーム先頭のクリップも全命令と一緒に比較するようにした。
- ExtGStateの部分更新で、以前に設定した透明度が消えないようにした。上書き済みの設定や、その描画が使わない塗り／線の状態は依存から外した。
- ページ本文のq/Q外クリッピングや、登録一覧の読み取り失敗を、正常な空グループとみなさないようにした。
- フォントの未知属性、未知Encoding、ToUnicodeの重複・未定義コード、文字クラスター数やword spacingの差を、フォントのみ変更した一致へ変換しないようにした。
- ページツリーの未知属性、Count不整合、循環を検査した。

## 検証

開発機: Windows、Python 3.14.8、Tk 9.0、pypdf 6.20.1、pytest 9.1.1。開発用venvで自動テストを行い、BAT・GUIの統合テストは通常Pythonとvendorソースだけでも実行する。

生成データの回帰テストに加え、ローカルに保存済みの未加工PDF-XChange Editor 11.1出力を再解析した。実ファイルは公開リポジトリに含めない。実出力がない環境では `test_xchange_integration.py` のみ理由を付けてスキップする。

重点条件は次のテスト群で確認する。

| 条件 | 確認内容 |
|---|---|
| A: フォントだけの変更 | ファミリー、埋め込みデータ、CIDのコード表現、DA / RC / DS / AP、複数フォント。非フォント差・復元不能の反例も検査 |
| B: DEMOの独立性 | 未加工出力の自己比較、日本語変更とDEMO増加、生成データでのDEMO描画・URI追加、未所属注釈を検査 |
| C: 保存識別子の差 | オブジェクト番号、Generation、格納順、圧縮、サブセット・参照名、注釈配列順を検査 |
| 独立したエラー | 未対応の独立区間・Action、追加・削除・重複名、未知登録一覧、共有状態・リソース依存 |
| GUI・出力・保護 | 基準変更、全判定表示、子プロセス比較・中止・時間制限、TXT/CSV/JSON、CSV無害化、原本・ハードリンクの保護 |
| オフライン実行 | 通常Python、site-packages無効、vendor不足の案内、venv未作成、BAT終了コード |

最終結果: **188件成功、失敗0件、スキップ0件**。このうちローカル実出力・原本保護の12ケースが成功した。サンプルがない環境で実行可能な生成データ・GUI・BAT等のテストは176ケース。未加工／加工データの条件と行ごとの結果は [実機検証記録](xchange-validation.md) に記録する。

```powershell
# 188 passed in 42.85s
```

WindowsのTk・ハードリンクも含め、プロジェクト内の一時フォルダーを使って制限外で最終実行した。原本2ファイルのSHA256は前回記録から不変だった。

## 残るリスクと次の作業

これは構造比較であり、任意のPDFを完全に解釈するレンダラーではない。未対応CMap、縦書き、Popup / IRT、OCMD / VE、複雑な継承状態、タグ付き構造、動的Action、非空フォーム等は検証不能になりうる。正規化の違いで、見た目が同じでも不一致が増えることがある。Rectは実際の最大描画領域を常に保証しないため、補助の重なり検査も完全な見た目の証明ではない。

pypdfの未発見の問題、フォントやビューアー固有挙動、数値の保守的な精度制限も残る。原本の正しさや全入力に共通する改変は証明できない。対応範囲を広げる際も、未知の構造を無視して一致を増やす変更は行わない。

次は日本語フォント・複数の保存方式・縦書き等の実出力を増やし、Windows 10 / 11、表示倍率、通常権限、オフライン実機、大きな図面の検証を追加する。今回は既存の保存済み実出力を利用した。Editor画面の追加操作はモニター取得エラーで再開できず、新規のEditor保存サンプルは増やしていない。
