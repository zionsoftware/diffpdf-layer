# 開発結果報告書

作成日: 2026-10-15 (JST)

**最終判定: CONDITIONAL GO — 対応範囲を限定した試作品として使用可能。実際の PDF-XChange Editor 出力による追加検証が必要。業務導入の GO ではない。**

## 1. 実装した主な機能

- Python 3.14.8 / pypdf 6.20.1 を用いたオフライン比較エンジン。GUI と分離。
- 2～4 ファイルの順序保持、全 1 / 3 / 6 組の比較。
- OCG 名の構成事前検査。不足するファイル・名前、重複名、不正参照を表示。構成不一致なら内容比較なし。
- ベース本文、同名レイヤーの注釈・独立した本文描画、表示状態、合成順序の比較。
- 日本語 Tkinter GUI。追加・削除・並べ替え・比較・中止・詳細・TXT/CSV/JSON 保存。
- 解析を子プロセスへ分離し、GUI 応答性を維持。180 秒の時間制限。
- start.bat / setup.bat、CLI、オンライン・オフライン別の導入文書。
- ソースだけの配布フォルダー生成ツール。pypdf ソースとライセンスを同梱し、バイナリをコピーしない。

## 3. OCG レイヤー比較の範囲

登録済みの単一 OCG を参照する注釈と、独立した q/Q 区間の marked content、直接 OC を持つ Form/Image に対応。全名前集合が一致することを要求し、任意の日本語・Unicode 名を扱う。既定・追加設定の値と OCG 属性を保持して表示状態の差を検出する。

OCMD / VE、異なるレイヤーのネスト、Form 内部の OCG、Usage / AS は解釈しない。PDF-XChange の一般的な出力にこれらが含まれていれば、同じファイル同士でも検証不能となる。安全のために制限しており、互換性を確認したことにはならない。

## 4. ベース PDF 比較の範囲

ページ数・属性、本文のテキスト・パス等の描画命令、使用するフォント・画像・描画状態リソースを正規化して比較。独立した OCG 区間と業務注釈を除去した構造を比較する。平坦化による本文への取り込みは本文命令の追加・変更として検出する。

画素比較やテキスト抽出だけに依存しない。リソースや命令の意味を完全に評価するレンダラーではないため、同じ見た目でも保存構造が変わると不一致になる場合がある。分離困難な構造は検証不能。全入力に共通する改変の存在や追加者の身元は判定できない。

## 5. 誤一致のリスクと対策・自己レビュー

- レイヤーだけを走査すると平坦化を見逃すため、本文命令・参照リソースも比較。
- OCG の参照を単に名前だけで解釈せず、登録された間接オブジェクトとの対応を検査。
- q/Q はパスを保存しないことを考慮し、marked content をまたぐパス・混在する描画区間を拒否。
- レイヤー外の描画状態が所属区間に影響するため、先行する本文状態もレイヤーの比較に取り込む。
- レイヤー別比較では重ね順変更を見逃すため、別の合成順序項目を追加。
- AP だけでなく、DA 等が参照しうるページリソースも注釈比較へ取り込む。
- pypdf の FloatObject の表示用丸めによる取りこぼしを修正。高精度の字句は拒否し、座標の微小差の回帰テストを追加。
- 未対応構造・警告・例外を一致に変換しない。同じ入力パスでも全解析を実施する。
- 循環の検出、深度・ファイル・ストリーム・命令数の上限、GUI のプロセス終了を実装。
- BAT の CLI 実行で終了コードが失われる問題を修正し、空の venv で回帰確認。

残るリスク: pypdf の未発見の解析問題、PDF 仕様・ビューアー固有動作との違い、未検証の実出力、注釈 subtype ごとの完全な妥当性検証不足。任意の PDF で誤一致が発生しないという保証はできない。未知の Catalog/ページ属性や複雑な構造を検証不能にし、実出力での回帰テストを導入する方針。

## 6. 未対応 PDF 構造

OCMD / VE / Usage / AS、Form 内部の OCG、混在する描画区間、非 OC BDC 属性、inline image、Type3、パターン、PostScript、外部参照、Popup / IRT 等の関連注釈、Widget / フォーム、タグ付き構造ツリー、暗号化、JBIG2 / CCITT 等。詳細は [対応一覧](supported-structures.md) を参照。

GUI 内のネイティブ DnD は実装していない。追加バイナリ依存を避け、ファイル選択を採用した。

## 7. オフライン導入

`tools/prepare_offline.py` で、プログラムのソースと、インストール済み pypdf 6.20.1 の純 Python ソース・ライセンスを `dist/offline-source` に作成する。EXE / DLL / .pyd / .pyc / wheel / 開発 venv はコピーしない。会社の審査後、このソースフォルダーのみをコピーし、承認済み Python から `setup.bat`、`start.bat` を実行する。

通常の pip による sdist ビルドに依存せず、vendor ソースを直接 import するため、オフラインでビルドツールを取得する必要はない。pypdf の著作権表示・ライセンスを維持する。pytest と開発依存のオフライン配布は別途手配が必要だが、本番比較には不要。詳細は [README](../README.md)。

## 8. PDF-XChange Editor で追加検証すべき事項

機密情報を含まない PDF を実ソフトで作成し、次の組を準備する。

1. 同一内容を「名前を付けて保存」「最適化」「増分保存」した組。未変更が一致または理由付き検証不能になること。
2. 各種類の日本語注釈、線・矢印・図形の値を 1 項目ずつ変えた組。Popup / IRT / RC / DA / AP / フォントも確認。
3. レイヤーの表示・印刷・書き出し状態、Usage / AS、ネストされた Form、OCMD を含む出力。
4. 所属移動、レイヤー外追加、平坦化、本文編集の組。差異または検証不能が返り、誤って一致しないこと。
5. 2～4 工程の業務想定データと大きめの図面。時間・メモリー・GUI の実用性。
6. Windows 10 / 11、表示倍率 100% / 150% / 200%、日本語パス、通常権限、オフライン PC での BAT 起動。

## 9. 次に実施すべき開発

最優先は実出力の匿名化サンプルを回帰テストへ追加すること。頻出する構造を確認した後、Popup / IRT の参照関係、Usage / AS、Form 内部の状態を保った OCG 分離の順に拡張する。複雑な描画状態を扱う際は、対応していない構造を検証不能にする原則を維持する。

業務用 PDF で十分な正例・変更例・異常例の検証が完了し、利用者が判定範囲を確認するまでは GO に変更しない。
