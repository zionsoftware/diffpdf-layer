# 順序非依存の内容比較・注釈作成者情報の分離

更新日: 2026-10-16。Python 3.14.8 / pypdf 6.20.1 / Tkinter、通常Pythonと手動vendor配置、オフライン実行、原本保護を維持した。

## 業務仕様

本プログラムは、PDF本体・レイヤーなし・各OCGレイヤーの内容を比較する。オブジェクトの重なり順や視認性は判定しない。チェックマーク・注記の視認性や妥当性は、担当者・確認者・審査者が目視で確認する。

注釈に記録された作成者名は、内容の同一性判定から除外し、参考情報としてグループごとに表示する。作成者名の変更だけでは不一致としない。作成者名は実際の操作ユーザーや最終編集者を証明する情報ではない。

## 変更範囲

## 順序非依存化と安全性

命令列を単純にソートしない。ページごとにq/Q・marked content・BT/ET・パスが閉じたトップレベル単位を切り出し、所属を確定する。各単位の使用リソースを解決し、使用した継承状態を付与してから、同じページ・同じグループ内の単位全体を順序非依存で比較する。同じ内容の単位の重複数も保持する。

同じ状態保存区間内の複数の完結したパス・BT/ET・呼び出しも、単純なq/Q・OC囲みで、クリッピングや追加の入れ子がなければ状態を再走査して個別に分離する。単一パス内のサブパス、一つのBT/ET内の文字順は分割しない。

単位内部の文字・パス・行列適用順・状態更新は保持する。Form XObject / Annotation Appearanceはストリーム全体の内部順序を保持する一単位である。独立したForm呼び出し全体の順序交換は許容する。単位を内部命令に分解する一般的な意味解析や、等価な座標変換への書き換えを証明する機能はない。

q/Q外のクリッピング、閉じていない状態、混在する所属、未知命令、未知リソース等で安全に分離できない場合は検証不能。問題の所属が確定すれば当該グループへ限定し、影響範囲が不明なら対象を広げる。DEMO描画やURI Linkは通常のレイヤーなしの内容であり、特別な除外はない。

通常値とフォントを分離した二次値の双方を同じ単位でマルチセット化する。フォント辞書・埋め込みデータを通常比較に残し、厳密なEncoding / ToUnicodeから文字を復元でき、文字・明示配置・非フォント属性が同じ場合だけ「一致（フォントのみ変更）」とする。未知のEncodingや曖昧なマッピングを推測しない。既存のfont_changesを保持する。

## 作成者名の分離と出力

注釈辞書の `/T` を内容の通常値・二次値から除く。`/Contents`・`/Subj`・独自属性は引き続き比較する。`/M`・`/CreationDate`・`/NM` の除外も維持する。内容解析を終えた後の独立した走査で `/T` を読むため、壊れた作成者参照やその解析警告が内容判定へ混ざらない。

レイヤーなし・各OCGについてPDFごとの名前別件数、欠落または空文字列の未設定件数、所属が既知の取得不能件数、集計の完全性・理由を保持する。名前は記録値のまま扱う。所属が不明な注釈は件数を推測して配分せず、影響する集計を未完了とする。内容が不一致や検証不能でも取得できた情報を表示する。

両PDFの集計が完全なら名前別件数と未設定件数の構成を比較し、独立したauthors_changedへtrue/falseを格納する。未完了ならnull。同一内容の複数注釈について個別の変更前後を捏造しない。構成が同じ場合の個別の付け替えまでは検出しない。

GUIは一覧の内容判定を維持し、選択行の詳細に双方の集計・構成変更・内容差異・フォント差異を表示する。TXTも同じ詳細を使用する。CSVは1グループ1行、従来5列に双方の集計・構成変更の3列を追加する。JSON schema_version 3はreference_authors / target_authors / authors_changedを持ち、counts / unset_count / unreadable_count / complete / group_present / errorsを構造化する。旧version 2は旧補助行を除き、旧判定を詳細に残しつつ検証不能へ変換し、元PDFでの再比較を案内する。

## 自己レビュー

- 作成者名だけの変更では通常一致を維持し、参考情報には差を残す。フォント同時変更はフォントのみ変更の一致と両立する。
- 重複描画・注釈の個数、重複する作成者名の件数、未設定と取得不能の区別を維持する。
- TDが暗黙に設定するleadingと、T*で使用してからTLで上書きするleadingの依存を追加した。継承状態の差を見逃さない。
- JSON読み戻し時に欠落した集計、不正件数、完全性・構成変更フラグの矛盾を拒否する。
- 旧矩形交差テストを、重なる／重ならない注釈の順序非依存比較・重複数検査で置き換えた。局所エラー、追加／削除、原本・ハードリンク保護の検査を維持した。

## 検証

開発機: Windows、Python 3.14.8、Tk 9.0、pypdf 6.20.1、pytest 9.1.1。開発用venvで実行し、BAT・GUIの統合テストは通常Pythonとvendorソースでも確認する。

生成PDFの回帰テストは、独立した矩形・線・矢印・Form呼び出し・グループ間の順序交換、内部順序・重複数・状態継承・文字位置・色・線幅・透明度、フォント変更と反例、作成者集計の完全性、各出力、旧JSON、原本保護を対象とする。

保存済みの未加工PDF-XChange Editor 11.1出力でも内容判定と作成者件数を再確認した。実ファイルと記録名は公開Gitへ含めない。サンプルがなければ実出力15ケースのみスキップする。詳細と結果は [実出力の検証記録](xchange-validation.md) を参照。

最終結果: **243件成功、失敗0件、スキップ0件（65.82秒）**。このうち保存済み実出力・作成者集計・原本ハッシュの15ケースが成功した。サンプルがない環境で実行できる生成データ・GUI・BAT等のテストは228ケース。最初の全体実行で判明したテスト用所属指定と旧GUI模擬データの不備も修正し、全体を再実行した。

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp=.venv/pytest-author-release --tb=short
# 243 passed in 65.82s
```

Tk・BAT・ハードリンクも含め、プロジェクト内の一時フォルダーを使って最終実行した。原本2ファイルのSHA256を前回の記録と照合し、比較対象を含むローカルPDF13個の比較前後のSHA256も不変だった。

## 残るリスク・未対応

任意のPDFを完全に解釈するレンダラーではない。複合単位内部の順序・等価な別命令・行列の書き換え等で、見た目が同じでも構造差が残る。未対応CMap、縦書き、Popup / IRT、OCMD / VE、複雑な継承状態、タグ付き構造、動的Action、非空フォーム等は検証不能になりうる。字形・字幅・暗黙の字送り・画素位置の完全一致は保証しない。

作成者名は自己申告的なPDF記録値であり、操作履歴や本人性を証明しない。pypdfやビューアー固有挙動、保守的な数値精度制限も残る。全入力に共通する改変や基準PDFの正しさは証明できない。

今回は既存Editor出力を再解析した。新しいEditor操作による順序交換・作成者名だけの変更・フォントだけの変更は未実施で、生成データによる確認と区別する。前回の画面取得エラー後、GUI自動操作を繰り返していない。Windows 10 / 11各版・DPI・通常権限・オフライン実機・大規模図面・各保存方式の追加検証は残る。
