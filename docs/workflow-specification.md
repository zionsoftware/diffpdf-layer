# 工程別比較の仕様

対象: diffpdf-layer 0.2.0。更新日: 2026-10-26。

この文書は、承認された変更計画を実装するための工程・判定・記録の共通仕様です。

## 入力と基準

入力は担当・確認・審査・承認の4役割です。担当・確認は必須、審査・承認はそれぞれ省略可能です。指定された中で承認、審査、確認の順に基準を選びます。審査なしで承認だけを追加する指定も有効です。同じファイルを異なる役割へ指定することもできます。

各入力は1回解析し、全組合せを比較します。2ファイルなら1組、3ファイルなら3組、4ファイルなら6組です。比較明細の方向は前工程から後工程へ向け、主表の基準は最後の工程です。

## 内容判定

内容は一致・不一致・検証不能の三分類です。レイヤーの追加・削除、および安全に分離できたフォントのみの変更は、不一致として詳細に理由を記録します。フォント差と文字差を安全に分離できない場合は従来どおり検証不能です。注釈の作成者名だけの変更は内容判定に含めません。

PDF全体は、PDF本体、レイヤーなし、両ファイルの全レイヤーの判定を集約します。1つでも不一致があれば不一致、なければ検証不能の有無、すべて一致なら一致の順です。SHA-256の一致を、内容の一致の代わりには用いません。

## 業務判定

| 比較 | 一致必須の業務レイヤー | 差異許容の業務レイヤー |
|---|---|---|
| 承認と審査 | 担当・確認・審査 | 承認 |
| 承認と確認 | 担当・確認 | 審査・承認 |
| 承認と担当 | 担当 | 確認・審査・承認 |
| 審査と確認 | 担当・確認 | 審査・承認 |
| 審査と担当 | 担当 | 確認・審査・承認 |
| 確認と担当 | 担当 | 確認・審査・承認 |

PDF本体、レイヤーなし、4業務名称以外の全レイヤーは、どの比較でも一致必須です。名前は完全一致で対応付けます。担当者・確認者等の別名や、前後に空白がある名前を自動補正しません。

一致必須の項目に確定した不一致があればFAILです。不一致がなく、必要な項目を検証できなければUNVERIFIABLEです。すべて検証できて一致した場合にPASSとなります。確定した不一致と検証不能が混在する場合はFAILを優先し、検証不能の理由も残します。

一方にしかないレイヤーは不一致です。必要な業務レイヤーが両方に存在しない場合はUNVERIFIABLEです。差異許容のレイヤーがない場合は、存在を必須としません。同名の重複は該当レイヤーを検証不能とします。許容レイヤー内だけの検証不能は、影響がそこに限定できる場合、PASSを妨げません。

## 表と記録

主表は基準PDFの登録レイヤー名を縦軸、指定役割を工程順に横軸として、各入力と基準の結果を示します。PDF全体・PDF本体・レイヤーなし・業務判定も掲載します。基準欄の「基準」は自己一致の判定を意味しません。基準にない追加レイヤーは「基準PDF外」として末尾に掲載します。対象と基準の双方にない追加名は「双方に該当なし」です。

全組合せのPDF全体・業務判定を別表に掲載し、各比較組のレイヤー別結果、差異理由、検証不能理由、作成者参考情報を詳細に記録します。前工程同士の判定も主表から推定せず、実際の比較結果を使います。

ファイルごとに役割、フルパス、最終更新日時（UTC・タイムゾーン付き）、バイト数、SHA-256先頭12桁を記録します。表示例は `abcdef-123456` です。JSONでは完全な64桁のハッシュも保存します。これは入力の識別情報であり、作成者や操作履歴の認証ではありません。

ハッシュは解析へ渡すバイト列から取得し、ファイル情報は開いた入力ハンドルから取得します。読み込み前後の識別情報・容量・更新日時、および読了後のパス情報の変化を検出したら、その入力は検証不能です。壊れたPDFでも読めたバイト列のハッシュは保持します。読めないファイルやサイズ上限を超えたファイルのハッシュは取得不能とし、部分データのハッシュを全体のハッシュとして表示しません。

## 保存と互換性

GUIでTXT・PDF・CSV・JSONを選択できます。既定名はcmp.txt、cmp.pdf、cmp.csv、cmp.jsonです。PDFはReportLabによるA4横の表で、日本語TrueTypeフォントを埋め込み、長いセルの折り返しと表見出しの繰り返しに対応します。TXTはUTF-8、CSVはUTF-8 BOM付きです。

JSONはschema_version=4です。roles、reference、file_info、pairs、layer_names、extra_names、results、errorsを保持し、明細にも左右の役割を記録します。同じパスを複数役割に指定しても組を区別できます。旧version 2・3は内容判定を検証不能へ変更し、元PDFによる再比較を案内します。旧業務判定を生成しません。

CSVはファイル情報、主表、組合せ一覧、比較明細の複数セクションとなります。明細は従来の8項目相当に左右の役割を追加した10列です。旧版の単一表として処理するスクリプトは更新が必要です。固定スキーマを必要とする自動処理にはJSONを使用してください。

保存は入力との同一パス・同一実体を拒否し、一時ファイルへ完全に書いてから置き換えます。生成失敗時は既存出力を保持します。既存の入力以外の出力は置換されるため、過去の結果を残す場合は保存先を変更してください。
