# 要件定義書

対象: diffpdf-layer 0.2.0。基準日: 2026-10-26。

## 1. 適用範囲

[要求定義書](requirements-definition.md)のURを、現行製品の検証可能な条件へ展開する。以下は現行実装と既存資料を照合した仕様である。バージョン条件・解析上限等は実装上の条件から整理したもので、過去の業務要求の存在を推定したものではない。確認方法のTCは[テスト仕様書](test-specification.md#cases)で定義し、部分検証・未検証は同書に明示する。

## 2. 用語と比較単位

| 用語 | 定義 |
|---|---|
| 基準PDF | 指定された最後の工程（承認、審査、確認の優先順）。正しさを認証したPDFではない |
| 比較対象PDF | 担当・確認・審査・承認として指定したPDF。全組合せを比較する |
| PDF本体 | ページ数・ページ属性・対応する文書属性等。本文描画すべてを意味しない |
| レイヤーなし | OCGに所属しない本文描画・注釈。DEMO描画・URI Linkも通常の対象 |
| 各OCGレイヤー | OCG名で対応付ける内容と設定。日本語・Unicode名を保持する |
| 独立した描画単位 | 所属・使用状態・資源を確定して完結した描画。単なるPDF命令1個ではない |

### 実装済み上限と保証の区別

| 項目 | 現行条件 | 適用上の注意 |
|---|---|---|
| 入力ファイル | 1ファイル128 MiB以下 | 読み込み時に上限+1バイトで確認 |
| ページ | 1～2000ページ | reader.pagesへのアクセス後に確認する |
| ストリーム・結合コンテンツ | 32 MiB以下 | 展開後に確認する。展開前のメモリー使用量制限ではない |
| 命令数 | content_operationsの1回の解析で100,000以下 | 解析後に確認。PDF全体の命令総数ではない |
| 正規化 | 深度70超、Canonicalizerごとのvalue呼出250,000超で拒否 | ファイル全体のノード総数・OSの強制メモリー上限ではない |
| その他 | 資源・ページツリーの深度、Form再帰、CMap等にも制限 | 正確な条件は[詳細設計DD-03](detailed-design.md#dd-03) |
| 処理時間 | GUI子プロセスの待機180秒 | 全比較対象を含む1回の実行。各PDFの処理時間保証ではない |

大量・悪意あるデータを隔離するOSサンドボックスや強制メモリー制限は実装していない。上限内なら一定時間以内に成功するという性能保証は設けない。過去の全テスト1060.90秒はテスト実行時間であり、単一PDFのベンチマーク値ではない。

## 5. 判定仕様

| 判定 | 条件・意味 | 注意事項 |
|---|---|---|
| 一致 | 対応範囲内の通常正規化値が同一 | 保存差の正規化と独立単位の順序差許容を含む。見た目・正しさの保証ではない |
| 不一致 | 安全に比較できる構造・内容に差がある | 見た目が同じ別構造でも不一致となりうる。詳細は代表的な最初の差であり、全差分一覧ではない |
| 検証不能 | エラー・未対応・所属不明・必要な文字復元不能等で判定を確定できない | 同じPDF同士でも起こりうる。不一致がないことを意味しない |

解析エラーを判定より優先し、その後に存在差、通常一致、フォント二次比較、不一致の順に判定する。フォントのみ変更・追加・削除は不一致に含める。PDF全体と業務判定の集約は[工程別比較の仕様](workflow-specification.md)に従う。作成者情報の構成変更は独立した補足情報であり、内容ステータスを変更しない。

## 6. 現行動作の注意と検証範囲

Python 3.14.8以外の3.14パッチ版や32bitを起動コードが一律拒否する実装にはなっていない。検証済み構成以外の動作を保証しない。--checkはTkinterのインポートを確認し、画面セッションの動作までは確認しない。

CLIでは不一致・グループ単位の検証不能でも終了コード0となりうる。ファイルエラー等のreport.errorsがあれば2となる。通常の保存エラーはerrorsへ追加し終了コード2とする。詳細は[詳細設計DD-10](detailed-design.md#dd-10)。これらを「全エラーが必ず2」「0なら全グループ一致」と定義しない。

要件と設計・テストの全対応は[トレーサビリティ表](test-specification.md#traceability)、未検証環境と検証上の不足は[未検証事項](test-specification.md#open-items)を参照する。
