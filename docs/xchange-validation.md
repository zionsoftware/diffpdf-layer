# PDF-XChange Editor 実機検証

実施日: 2026-10-16。Windows 上のインストール済み PDF-XChange Editor 11.1.0.0 を操作して確認した。入力は利用者指定の未追跡 PDF 2 ファイル (1up / 2up、各4ページ)。作業コピーだけを Editor で編集し、原本は変更していない。

評価版の DEMO スタンプを許可した条件で実施した。原本、Editor の保存結果、加工した検証用コピー、機械可読な結果はローカルの `output/xchange-validation` に保存し、Git 管理対象には含めない。再実行用の `validate.py` も同じ場所に置いた。

## 確認した動作

| 操作・比較 | 結果 |
|---|---|
| 原本2ファイルそれぞれの自己比較 | 一致 |
| 両方を Editor で開き、変更せず別名保存したものと原本を比較 | 一致 |
| 1up に日本語名「検証者A」「検証者B」のレイヤーを作成 | 構成検査成功。評価版の Link 注釈により内容比較は検証不能 |
| 検証者Aに矢印・矩形・日本語のタイプライター注釈を作成 | 保存成功。下記の加工コピーで自己比較が一致 |
| 日本語注釈の末尾 A を B に変更して別名保存 | 加工コピーで検証者Aが不一致、空の検証者Bは一致。本文・合成順序も追加 DEMO 描画によって不一致 |
| 2up にレイヤー未所属の矩形注釈を追加 | 検証不能。未所属注釈を一致と判定しない |

Editor の保存結果には、DEMO 描画と、その上の URI アクション付き `/Link` 注釈があった。Link は未対応で、OCG にも所属していない。これらを無視して一致にする処理は追加していない。

レイヤー・注釈解析を個別に確認するため、pypdf で **Link 注釈だけを取り除いた別ファイル** を作成した (`*-no-demo-links.pdf`)。DEMO の描画、レイヤー、矢印・矩形・日本語注釈は残した。この加工コピーの結果を、Editor の未加工出力の互換性確認と同一視しない。

今回の評価版では、編集後の保存ごとに DEMO の Artifact 描画が各ページで2つ増えた。日本語変更の前後では、各ページのウォーターマーク BDC が4個から6個へ増え、1ページ目の本文命令が637個から649個へ増えた。この実際の本文差を不一致として検出するのは意図した動作である。また、注釈用の既定フォントリソースの変更は、そのリソースを共有する他の同一レイヤー注釈にも不一致を生じさせることがある。

## 見つかった問題と修正

- 入力 PDF の `/Trans {}` で自己比較さえ検証不能だった。空辞書を既定の無効果状態として正規化し、実際の遷移パラメーターは比較対象として残した。
- Editor が作る OCG の `/Usage` と `/AS` に対応できなかった。View / Print / Export の限定した状態辞書と参照を検査し、値を保持して比較するようにした。言語・ズーム等の条件や OCMD は未対応のまま。
- DEMO の `/Artifact` 属性を含む BDC に対応できなかった。属性辞書や名前付き Properties 参照を検査し、ActualText 等も含めて比較するようにした。
- 日本語タイプライター注釈に伴う、Fields が空の `/AcroForm` を拒否していた。Fields が空で、任意の DR だけを持つ場合に限定し、フォント等を所属注釈の比較に含めた。非空フォーム、XFA、その他の属性は拒否する。
- 同じ埋込フォント等の参照を繰り返し検査していた。検査・正規化が完了した辞書を解析中に再利用し、循環検出・深度制限は維持した。

これらは実構造を模したコード生成 PDF による回帰テストでも確認する。利用者指定 PDF の内容はテストソースへ埋め込まない。

## 未検証の範囲

ライセンス適用済み環境の未加工レイヤー出力、最適化・増分保存、Popup / IRT を持つ注釈、所属移動、Editor による平坦化、本文編集、複雑なネストや条件付き OCG、大規模図面、Windows 10 / 11・高 DPI の組み合わせは追加検証が必要。平坦化・所属移動等のコード生成 PDF の回帰テストは実施しているが、Editor での実機検証とは区別する。

判定は **CONDITIONAL GO** を維持する。今回確認した限定した構造への対応であり、任意の Editor 出力や業務用 PDF 全体に対する保証ではない。
