更新日: 2026-10-16。PDF-XChange Editor 11.1.0.0の保存済み実出力に加え、今回新たに作成した変更なしの別名保存を検証した。利用者が許可した評価版DEMOスタンプを含む。

## サンプルと保護

利用者指定の未追跡PDFは `tests/mixed_1up_8pt.pdf` と `tests/mixed_2up_8pt.pdf` (各4ページ)。作業コピー・Editor保存結果・前回の加工コピーは `output/xchange-validation` にある。元PDFとEditorの未加工出力を今回の比較で書き換えない。元PDFのSHA256を前回の `original-hashes.json` と照合する。

前回は、レイヤー未所属注釈を異常とする旧仕様により、DEMOのURI Linkを含む未加工出力が検証不能だった。この制約は新仕様で廃止した。DEMOを除外する例外処理は追加していない。URI Linkは開かずに辞書を比較し、描画とリンクを通常のレイヤーなしへ分類する。

### GUI中断と残るケース

今回、最初の画面取得と操作は成功した。Aの保存後、コメント選択で日本語タイプライターを選び、右クリック→プロパティ→一般→作成者で検証用の名前へ変更し、Enterで確定した。しかし、その後の別名保存で `failed to activate captured window` が発生した。ウィンドウを再選択し画面取得を一度回復した後、再試行した入力で `GetCursorPos failed: アクセスが拒否されました。 (0x80070005)` が発生したため、以後のGUI操作を中止した。RDP等が原因かは断定していない。

作成者名を変更したPDFは保存できていない。ディスク上の `a-resaved.pdf` はAの変更なし保存のままで、Bの実出力として扱わない。Editorには `a-resaved*` の未保存編集が残っている可能性がある。既存のファイルへ保存せず、新規名で保存するか、手動で未保存変更を破棄してから基準コピーを開き直す。

## 注釈の作成者名（PDF記録値）

未加工の `one-annotations-a/b` と `two-unassigned` を、pypdfによる直接の注釈辞書走査と独立に照合した。名前の実値は公開文書に転載せず、Git管理外のローカルレポートに保持する。

| グループ | one-annotations-a | one-annotations-b | 集計 |
|---|---|---|---|
| レイヤーなし | 名前なし、未設定16件 | 名前なし、未設定24件 | 完了。構成変更あり |
| 検証者A | 1種類の記録名、3件 | 同じ記録名、3件 | 完了。構成変更なし |
| 検証者B | 注釈なし | 注釈なし | 完了。構成変更なし |

検証者Aの内容不一致と作成者名構成の変更なしを同時に出力する。自己比較は内容一致・構成変更なしとなる。GUIと同じデータからTXT / CSV / JSONを生成し、JSONの読み戻しでも集計と内容判定が保持される。再解析前後でローカルの原本・コピー・保存出力・前回加工コピー計13個のPDFのSHA256が不変であることを確認した。

注釈に記録された作成者名は、内容の同一性判定から除外し、参考情報としてグループごとに表示する。作成者名の変更だけでは不一致としない。作成者名は実際の操作ユーザーや最終編集者を証明する情報ではない。

## 加工コピーとの区別

前回の `*-no-demo-links.pdf` は、pypdfでLink注釈だけを取り除いた別ファイルであり、Editorの未加工出力ではない。DEMO描画、OCG、矢印・矩形・日本語注釈は残っている。新仕様でも別の検証ケースとして比較し、日本語変更が検証者A、DEMO描画増加がレイヤーなしへ現れ、PDF本体・検証者Bが一致することを確認する。

今回の重点検証は未加工の方である。新仕様では未加工出力からLinkを除く必要はない。

## フォント変更・DEMOだけの変更の根拠

保存済みの未加工サンプルに、フォントだけを変更した組、作成者名だけを変更した組、独立描画の順序だけを交換した組や、全注釈が同じでDEMOだけが増えた組はない。このため、これらをEditor実出力で確認済みとは主張しない。順序交換・作成者名変更・フォントと作成者名の同時変更はコード生成PDFで検証する。

重点条件Aのフォント変更は、コード生成PDFでファミリー、埋め込みデータ、CIDコード変更、AP、DA、RC、DS、複数フォントと反例を検証する。重点条件Bの「DEMO描画やURI Linkだけが増えても、同じA/Bが一致する」は、DEMO構造を模した生成データで検証する。未加工実出力では、DEMO増加と日本語変更の影響が別グループへ分離されることを確認した。

前回の追加サンプル作成の試行では、`GetCursorPos` のアクセス拒否に続き、再取得時に `IGraphicsCaptureItemInterop.CreateForMonitor` のモニター取得エラーが発生した。今回の再試行で作成できた新しい実出力は上記Aだけで、Editor上のフォント変更操作は今回も未実施である。

## 再実行

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_xchange_integration.py -q
```

サンプルが存在すれば未加工・加工・作成者集計・原本ハッシュの16ケースを検査する。PDFやローカル結果はGitへ登録しない。サンプルがない環境では理由を付けてスキップする。通常の生成データテストは実行できる。

本プログラムは、PDF本体・レイヤーなし・各OCGレイヤーの内容を比較する。オブジェクトの重なり順や視認性は判定しない。チェックマーク・注記の視認性や妥当性は、担当者・確認者・審査者が目視で確認する。

Popup / IRT、所属移動、Editorによる平坦化、最適化・増分保存、大規模図面、Windows各版・DPI・オフライン環境は追加検証が必要。生成データによる平坦化・所属移動の検査と、Editorでの実操作は区別する。
