# PDF-XChange Editor 実出力のグループ別検証

更新日: 2026-10-16。インストール済みPDF-XChange Editor 11.1.0.0で前回作成したローカルの実出力を、新仕様のエンジンで再解析した。利用者が許可した評価版DEMOスタンプを含む。

## サンプルと保護

利用者指定の未追跡PDFは `tests/mixed_1up_8pt.pdf` と `tests/mixed_2up_8pt.pdf` (各4ページ)。作業コピー・Editor保存結果・前回の加工コピーは `output/xchange-validation` にある。元PDFとEditorの未加工出力を今回の比較で書き換えない。元PDFのSHA256を前回の `original-hashes.json` と照合する。

前回は、レイヤー未所属注釈を異常とする旧仕様により、DEMOのURI Linkを含む未加工出力が検証不能だった。この制約は新仕様で廃止した。DEMOを除外する例外処理は追加していない。URI Linkは開かずに辞書を比較し、描画とリンクを通常のレイヤーなしへ分類する。

## 未加工Editor出力の結果

| 基準 → 比較対象 | PDF本体 | レイヤーなし | 検証者A | 検証者B |
|---|---|---|---|---|
| 原本1up → one-resaved (変更なし保存) | 一致 | 一致 | 対象なし | 対象なし |
| 原本2up → two-resaved (変更なし保存) | 一致 | 一致 | 対象なし | 対象なし |
| one-layers の自己比較 | 一致 | 一致 | 一致 | 一致 |
| one-annotations-a の自己比較 | 一致 | 一致 | 一致 | 一致 |
| one-annotations-b の自己比較 | 一致 | 一致 | 一致 | 一致 |
| one-annotations-a → one-annotations-b | 一致 | 不一致 | 不一致 | 一致 |
| two-resaved → two-unassigned | 一致 | 不一致 | 対象なし | 対象なし |

`one-annotations-a/b` は検証者Aの矢印・矩形・日本語タイプライター注釈を含む。Bでは日本語注釈の末尾AをBへ変更した。Editorの評価版保存により、各ページのウォーターマークBDCが4個から6個に増え、1ページ目の本文命令が637個から649個へ増えた。未加工のまま、文字変更を検証者A、DEMO増加をレイヤーなしとして検出し、PDF本体と未変更の検証者Bは一致した。重なるDEMO Linkの追加により、補助の合成順序にも差がある。

原本2ファイルと `two-unassigned` の自己比較も全グループが一致する。2upに追加した未所属の矩形は異常ではなく、レイヤーなしの差として検出される。

## 加工コピーとの区別

前回の `*-no-demo-links.pdf` は、pypdfでLink注釈だけを取り除いた別ファイルであり、Editorの未加工出力ではない。DEMO描画、OCG、矢印・矩形・日本語注釈は残っている。新仕様でも別の検証ケースとして比較し、日本語変更が検証者A、DEMO描画増加がレイヤーなしへ現れ、PDF本体・検証者Bが一致することを確認する。

今回の重点検証は未加工の方である。新仕様では未加工出力からLinkを除く必要はない。

## フォント変更・DEMOだけの変更の根拠

保存済みの未加工サンプルに、フォントだけを変更した組や、全注釈が同じでDEMOだけが増えた組はない。このため、これらをEditor実出力で確認済みとは主張しない。

重点条件Aのフォント変更は、コード生成PDFでファミリー、埋め込みデータ、CIDコード変更、AP、DA、RC、DS、複数フォントと反例を検証する。重点条件Bの「DEMO描画やURI Linkだけが増えても、同じA/Bが一致する」は、DEMO構造を模した生成データで検証する。未加工実出力では、DEMO増加と日本語変更の影響が別グループへ分離されることを確認した。

Editorを再操作して追加サンプルを作る試行では、`GetCursorPos` のアクセス拒否に続き、再取得時に `IGraphicsCaptureItemInterop.CreateForMonitor` のモニター取得エラーが発生した。今回の実機検証は既存の保存済みデータの再解析であり、新しいEditor上のフォント変更操作は行っていない。

## 再実行

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_xchange_integration.py -q
```

サンプルが存在すれば未加工・加工・原本ハッシュの12ケースを検査する。PDFやローカル結果はGitへ登録しない。サンプルがない環境では理由を付けてスキップする。通常の生成データテストは実行できる。

Popup / IRT、所属移動、Editorによる平坦化、最適化・増分保存、大規模図面、Windows各版・DPI・オフライン環境は追加検証が必要。生成データによる平坦化・所属移動の検査と、Editorでの実操作は区別する。
