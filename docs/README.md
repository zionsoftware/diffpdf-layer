# ドキュメント一覧

diffpdf-layer 0.1.0の文書案内です。文書整備基準日: 2026-10-16。[製品README](../README.md)へ戻る。

## 正式文書

| 文書 | 役割・読むと分かること |
|---|---|
| [要求定義書](requirements-definition.md) | 何のために必要か。一般的な利用者の目的、12要求、対象外、成功条件 |
| [要件定義書](software-requirements.md) | 何を満たすか。24機能要件・9非機能要件、受入基準、6判定、現行制約 |
| [基本設計書](basic-design.md) | 全体をどう実現するか。構成・画面・グループ・比較フロー・保護方針 |
| [詳細設計書](detailed-design.md) | 実装でどう処理するか。実在モジュール・関数・データ・分岐・制限・例外範囲 |
| [テスト仕様書・検証結果](test-specification.md) | 何を確認できたか。34試験項目、要求→要件→設計→テストの対応、実行履歴、未検証事項 |
| [ユーザーマニュアル](user-manual.md) | どう操作して結果を読むか。起動・入力・比較・中止・保存・判定と参考情報・FAQ |
| [インストール・セットアップ手順書](installation-guide.md) | どう準備するか。通常Python、ソースZIP、pypdf手動配置、BAT、環境確認、更新 |

利用開始にはインストール手順書→ユーザーマニュアル、仕様確認には要求→要件→設計→テストの順を推奨します。要求IDはUR、要件IDはFR/NFR、試験項目IDはTC、設計参照はBD/DDで識別します。

要求の分類とIDは既存製品仕様から再構成したもので、過去の要求合意を証明する資料ではありません。設計書には現行実装の事実、テスト仕様書には実行済み条件と未検証条件を分けて記載しています。

## 保守時の更新順

仕様変更は要求・要件への影響を確認し、基本設計→詳細設計→テスト対応→操作・導入手順→READMEの順に整合を確認します。実装の存在だけで過去の要求を補わず、確認できない性能や環境を検証済みとしないでください。単純な誤記は修正し、仕様判断が必要な矛盾は決定を記録してから更新します。

実装の構造は[src](../src/pdf_layer_compare)、起動処理は[main.py](../main.py)・[start.bat](../start.bat)、自動テストは[tests](../tests)を参照してください。
