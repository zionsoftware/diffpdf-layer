# PDFレイヤー同一性検証ツール (diffpdf-layer)

2～4 個の PDF を指定し、**1番目を基準PDF**として、2番目以降と個別に比較する Windows 向けのツールです。「PDF本体」「レイヤーなし」「各 OCG レイヤー」を独立して調べます。任意の日本語・Unicode レイヤー名に対応します。PDF 全体の総合一致判定は出力しません。

**PDF-XChange Editor 11.1 の限定した実出力で検証済みです。利用時の最終判断は利用者が行ってください。** 未対応構造があるグループは、内容が同じように見えても「検証不能」になります。

評価版の DEMO 描画や一般的な URI Link 注釈は「レイヤーなし」で比較します。DEMO を無視する処理や URI の実行は行いません。スタンプの追加で無関係なレイヤーが不一致になることはありません。検証条件と結果は [実機検証記録](docs/xchange-validation.md) を参照してください。

## 動作環境

- Windows、Python **3.14.8 (64bit)** + Tcl/Tk。開発機で Tk 9.0 を確認。
- 実行時の外部依存は **pypdf 6.20.1** のみ。Tkinter は Python 標準の配布物を使用。
- 開発テスト用: pytest 9.1.1。利用者の PC には不要。
- 実行にはインストール済みの Python をそのまま使います。venv の作成・参照や pip によるインストールは行いません。
- 実行時にインターネット、クラウド、外部 API は使いません。EXE 化も不要です。
- Windows 10 / 11 の両方を使った実機検証は未実施です。

## オンライン側での準備

オンライン側では、ブラウザーで次の 2 つのソース ZIP をダウンロードするだけです。Python、自作プログラム、PowerShell、BAT を実行する必要はありません。

1. [このツールの GitHub](https://github.com/zionsoftware/diffpdf-layer) の「Code → Download ZIP」。
2. [pypdf 6.20.1 の公式リリース](https://github.com/py-pdf/pypdf/releases/tag/6.20.1) の「Source code (zip)」。**最新版ではなく 6.20.1 を選んでください。**

取得した ZIP をオフライン環境へコピーします。ZIP の展開・ソースの配置はオフライン側で手動で行います。

## オフライン環境のセットアップ

Python 3.14.8 (64bit、Tcl/Tk を含む) をインストール済みであることが前提です。Python 本体の導入は別途行ってください。

### pypdf のコピー元と配置先

1. ツールの ZIP を展開します。`main.py`、`start.bat` があるフォルダーがツールのルートです。以下では `C:\dev\diffpdf-layer` を例にします。
2. pypdf の ZIP を展開します。展開した外側の `pypdf-6.20.1` フォルダーの中に、**内側の `pypdf` フォルダー**と `LICENSE` があります。
3. ツールのルートに `vendor` フォルダーを作成し、次のとおりコピーします。

| コピー元 (pypdf の ZIP 展開先) | コピー先 (ツールのルートからの相対位置) |
|---|---|
| `pypdf-6.20.1\pypdf` フォルダー全体 | `vendor\pypdf` |
| `pypdf-6.20.1\LICENSE` ファイル | `vendor\pypdf-LICENSE.txt` (コピー時に名前を変更) |

`pypdf` フォルダーは、`.py` ファイルだけを選別せず、サブフォルダーや `py.typed` も含めて丸ごとコピーしてください。外側の `pypdf-6.20.1` を配置したり、`__init__.py` だけをコピーしたりすると動作しません。pypdf のテストやドキュメントをコピーする必要はありません。

配置後は次の構成になります。

```text
diffpdf-layer/
├── main.py
├── start.bat
├── src/
├── tools/
└── vendor/
    ├── pypdf-LICENSE.txt
    └── pypdf/
        ├── __init__.py
        ├── _reader.py
        ├── _writer.py
        ├── generic/
        └── ... (残りのファイル・サブフォルダーもすべて)
```

### 確認と起動

`start.bat` をダブルクリックしてください。起動時に Python・Tkinter・手動配置した pypdf 6.20.1 を確認し、問題がなければ GUI を表示します。**事前のセットアップ操作は不要です。venv 作成・pip 実行・ネット接続・ZIP の自動展開は行いません。**

pypdf がない場合は、コピーするフォルダーと配置先を表示して終了します。コピー不足や別バージョンの場合も、フォルダー全体の再配置を案内します。システム側に pypdf がインストール済みでも、ツール内の `vendor/pypdf` が必要です。

BAT は `py -3.14`、次に PATH 上の `python` を確認して、仮想環境外の Python 3.14 を使用します。ツールの `.venv` は参照しません。PATH が仮想環境を指していて通常の Python を検出できない場合や、Windows Store のエイリアスを指す場合は、環境変数 `DIFFPDF_PYTHON` にインストール済み `python.exe` のフルパスを指定してください。

例えば、オフライン側のコマンドプロンプトで次のように指定できます。

```bat
cd /d C:\dev\diffpdf-layer
set "DIFFPDF_PYTHON=C:\Users\ユーザー名\AppData\Local\Programs\Python\Python314\python.exe"
start.bat
```

この `set` は同じコマンドプロンプト内で有効です。ダブルクリック起動でもパスを指定したい場合は、Windows のユーザー環境変数として `DIFFPDF_PYTHON` を設定してください。

## 起動と操作

1. `start.bat` をダブルクリックします。
2. 「PDF を追加」で 2～4 個指定します。フルパスと入力順を表示します。
3. 1番目に「基準PDF」が明示されます。「上へ」「下へ」で基準と入力順を変更し、「比較開始」を押します。
4. 基準と各比較対象の PDF本体・レイヤーなし・各レイヤーの結果を確認します。行を選ぶと差異・フォント変更・検証不能の原因を表示します。合成順序は独立した補助項目です。
5. 「結果を保存」でテキスト / CSV / JSON を保存できます。

原本はバイナリ読み取りでメモリーへ読み込み、書き込みません。入力 PDF 本体・別名のハードリンクへの結果上書きも拒否します。結果にはファイル名・パスや注釈文の一部が含まれる場合があるため、PDF と同様に適切に保管してください。

ファイルの GUI 内へのドラッグ＆ドロップは未対応です。PDF を `start.bat` にドロップして起動する方法は引数の受け取りに対応していますが、Explorer からのドロップ操作自体は未検証です。バイナリ依存の DnD 拡張は導入していません。

GUI の比較は別プロセスで実行します。中止可能で、180 秒経過時はプロセスを終了し検証不能と表示します。メモリー使用量の OS レベルの強制上限は設けていません。

### コマンドライン

```bat
start.bat --cli "工程1.pdf" "工程2.pdf"
start.bat --json --output "結果.json" "工程1.pdf" "工程2.pdf"
start.bat --check
```

終了コードは `0`: グループ別レポートを生成、`2`: 引数・環境・ファイル読み込み等のエラーです。`0` は内容が一致したという意味ではありません。グループの判定はレポート内で確認してください。CLI / エンジン直接呼び出しには GUI の 180 秒制限はありません。

## 判定と対応範囲

| 判定 | 意味 |
|---|---|
| 一致 | 対応範囲内で同一 |
| 一致（フォントのみ変更） | 後述の条件でフォント関連の差だけと確認。業務上は一致の一種 |
| 不一致 | 文字、配置、サイズ、色、図形、画像、注釈属性等に差がある |
| 新規追加 | 基準にないレイヤーが比較対象にある |
| 削除 | 基準にあるレイヤーが比較対象にない |
| 検証不能 | 未対応・破損・曖昧な所属や依存関係があり、安全に判定できない |

- PDF本体はページ数・サイズ・回転・ページ構造等を比較します。本文描画や注釈は二重計上せず、OCG 所属に従ってレイヤーなしまたは各レイヤーへ分類します。
- 全入力のレイヤー名の和集合を使います。各組の両方に存在しない名前は表示しません。重複名はその名前を検証不能とし、他グループの比較を続けます。
- 未所属の注釈は通常のレイヤーなしの内容です。壊れた所属参照や OCMD を未所属へ振り替えることはありません。
- 問題をグループ内へ限定できる場合、そのグループだけを検証不能にします。所属や状態の影響範囲が不明な場合は範囲を広げ、ファイル全体を読めない場合はそのファイルを含む組を検証不能にします。
- 実際に参照したフォント・画像・描画状態等を比較します。未使用フォントや AcroForm の未使用既定フォントは無関係な注釈に含めません。表示状態も対象レイヤーへ分けて比較します。
- オブジェクト番号・Generation・格納順・辞書キー順・対応するロスレス圧縮・保存日時 / NM を正規化します。注釈は個数を保持したマルチセットで比較します。
- 本文命令の実行順は保持します。注釈配列の並べ替えで内容が同じなら各グループは一致し、矩形が重なる注釈の順序差は別項目の `合成順序` で検出します。追加スタンプの重なりも補助項目に差として出る場合があります。
- レイヤー内容の平坦化は元レイヤーとレイヤーなしの変化として検出します。追加者・作成履歴や、全入力に共通の改変の正しさは証明できません。

### フォントのみ変更した一致

まず通常の構造比較を行います。差がある場合だけ、実際に使うフォントと文字コードの対応を調べ、**文字内容・明示した配置・サイズ・色・透明度・その他の内容が同じ**と確認できれば「一致（フォントのみ変更）」にします。可能な名前と変更内容を詳細へ表示し、JSON には専用ステータスと `font_changes` を出力します。内部名や CSS の申告名であり、正式なフォント名と断定しません。

本文、FreeText の DA / RC / DS、Appearance Stream、埋め込みフォント、CID フォント、AcroForm の使用した既定フォントを対象とします。同じフォントデータのサブセット接頭辞・参照名だけの違いは通常の一致です。

文字復元は限定した ToUnicode CMap、明示した標準エンコーディング等だけに対応します。CID は Identity-H + ToUnicode に限定します。未知のコード・曖昧な対応・自動サイズ等がある場合に、推測してフォント変更付き一致にすることはありません。

フォントを変えると字形・字幅・改行などの見た目が変わりえます。この判定は宣言された文字と配置命令等の**構造比較**であり、画素一致、フォントデータの正当性、PDF 仕様全体の意味的同一性、各文字の見た目の完全一致を保証しません。

詳細: [対応・未対応構造](docs/supported-structures.md)、[技術調査](docs/technical-investigation.md)、[開発結果報告](docs/development-report.md)。

## 構成

`src/pdf_layer_compare` 内で GUI・解析・OCG 検査・注釈・本文・フォント・比較・出力を分離しています。`tests` は機密情報を含まない PDF をコードから一時生成します。ローカルの `output/xchange-validation` が存在すれば未加工 Editor 出力の追加テストも行い、存在しなければそのテストだけスキップします。実際の PDF・出力結果を公開 GitHub に登録しないでください。

## 開発・テスト用の補助機能

以下は開発用です。利用者の導入手順では実行不要です。実行用 BAT が開発用 venv を使用することはありません。

- 自動テストは pypdf 6.20.1 と pytest 9.1.1、および pytest の依存が導入済みの開発環境で `python -m pytest` を実行します。開発用 venv の利用は任意です。開発依存の一覧は `requirements-dev.txt` にあります。
- `tools/prepare_offline.py` は、pypdf がインストール済みの開発環境でソース一式を複製する補助ツールです。通常の ZIP ダウンロード・手動配置方式には不要です。オンライン側で実行する必要はありません。
- `vendor`、開発用 `.venv`、生成した `dist` は Git 管理対象外です。GitHub のツール本体の ZIP には pypdf は含まれません。
